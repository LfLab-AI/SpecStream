# 创新点二与创新点三测试流程索引

本文档同时覆盖两类实验：第一类让创新点二、三脱离创新点一单独运行；第二类把创新点一分别与创新点二、三联合运行。两类结果都要保留，不能相互替代。

新增文档已经统一改为原有的“终端 A/终端 B/终端 C 直接执行”方式。完整 Target、Draft 和 benchmark 命令直接写在代码块中，不再使用 `export SPECSTREAM_TARGET_CMD=...`、`export SPECSTREAM_DRAFT_CMD=...` 或 `export SPECSTREAM_BENCH_CMD=...` 保存长命令。

GPU 统一使用 `CUDA_VISIBLE_DEVICES=0/1/2`。执行前先运行 `nvidia-smi -L`，按服务器实际可见编号调整。

所有新增 Draft 启动命令都加入了小显存配置：限制 Draft KV token 池、并发请求数、SPECTRE batch，并关闭 Draft CUDA Graph/Radix Cache。这样 0.5B Draft 不会再自动占用几乎全部剩余显存。创新点二 step1 还提供了“平衡、保守、仅 smoke”三档配置。

## 1. 创新点二：资源感知的卡内 Draft-Verify 并行

创新点二要回答的问题是：能否把 Draft 和 Target 放在同一张物理 GPU 上，在少用一张 GPU 的同时，把 Target 变慢、Draft 超时和尾延迟控制在可接受范围内？

按以下顺序执行：

1. `创新点二_step1_分卡与无控制基线测试.md`
   - 先测原生 GPU KV 下 Draft、Target 分卡运行的强 baseline。
   - 再测同卡但不做资源限制的对照。
   - 目的：得到“性能上限”和“直接共卡的干扰下限”。
2. `创新点二_step1补充_原生推测解码显卡缓存对照测试.md`
   - 检查所有创新点二、三命令都使用原生 GPU-resident KV，并确认 CPU/H2D 指标为 0。
   - 目的：防止创新点一的卸载策略混入实验，让创新点二、三能单独归因。
3. `创新点二_step2_单卡静态配额扫描测试.md`
   - 扫描 Target/Draft 的 90/10、80/20、70/30、60/40 静态 MPS 配额。
   - 目的：确认是否存在可用的同卡资源区间。
4. `创新点二_step3_动态共执行与反压测试.md`
   - 在最佳静态配额上开启资源感知控制、动态 q 和过载回退。
   - 目的：验证动态控制是否优于最佳静态配额，并保证高并发时服务不崩溃。

如果创新点二 step2 的所有静态配额都明显负优化，并且单位 GPU 有效吞吐也没有收益，应先执行 No-Go，不要直接投入更复杂的动态控制。

## 2. 创新点三：多 GPU 分层并行与 Straggler 控制

创新点三要回答的问题是：当 Target 使用 TP=2/4 等多卡并行时，Draft 与某个 Target rank 共卡，能否避免该 rank 变成慢节点并拖慢整个 TP 组？

按以下顺序执行：

1. `创新点三_step1_多卡独立草稿模型基线测试.md`
   - Target 使用 TP=2，Draft 使用额外独立 GPU。
   - 目的：建立没有共卡干扰的 P0/H0 强 baseline。
2. `创新点三_step2_多卡朴素共卡测试.md`
   - Draft 与 Target rank 0 共卡，但不开启 TP 慢节点保护。
   - 目的：测出共卡造成的 rank 时间差和整体 Target slowdown。
3. `创新点三_step3_多卡慢节点控制测试.md`
   - 在相同硬件布局和 MPS 配额下开启 TP straggler-aware 控制。
   - 目的：验证控制器能否压低 rank 时间差、减少 P99，并提高单位 GPU 有效吞吐。

创新点三必须同时报告总吞吐和 `goodput/GPU`。P0 baseline 使用 3 张物理 GPU；P1 共卡组使用 2 张物理 GPU，不能只比较总吞吐而忽略 GPU 数量。

## 3. 创新点一与创新点二联合测试

按顺序执行：

1. `创新点一与创新点二_step1_联合分卡与同卡基线测试.md`
   - 开启 KV 分层卸载，比较 Draft/Target 分卡与无控制同卡。
   - 目的：建立联合方案的性能上限和干扰下限。
2. `创新点一与创新点二_step2_联合分层缓存与静态配额测试.md`
   - 保持 KV 分层卸载，扫描单卡静态 MPS 配额。
   - 目的：找出联合方案可稳定运行的资源范围。
3. `创新点一与创新点二_step3_联合分层缓存与动态共执行测试.md`
   - 同时开启 KV 分层卸载、动态 q、共执行和反压；最后可选开启 Cohort。
   - 目的：验证创新点一是否为同卡运行释放显存，以及创新点二是否能控制竞争。

主要比较：联合 step3 与“不使用创新点一”的创新点二 step3。除了 KV 路径，其余模型、配额和负载必须相同。

## 4. 创新点一与创新点三联合测试

按顺序执行：

1. `创新点一与创新点三_step1_联合多卡独立草稿基线测试.md`
   - Target 使用 TP=2 和分层 KV，Draft 独占第 3 张 GPU。
2. `创新点一与创新点三_step2_联合多卡朴素共卡测试.md`
   - 使用分层 KV，Draft 与 rank 0 共卡，但不开慢节点保护。
3. `创新点一与创新点三_step3_联合分层缓存与慢节点控制测试.md`
   - 同时开启分层 KV、共卡控制和 TP 慢节点保护；最后可选开启 Cohort。

主要比较：联合 step3 与“不使用创新点一”的创新点三 step3，同时还要分别对照联合 step1、step2。

## 6. 所有实验共同遵守的规则

1. 使用相同的 Target、Draft、精度、数据集、随机种子、输入长度、输出长度、请求数和并发数。
2. 每个正式实验点完整重启 Target 和 Draft，预热后至少重复 3 次，报告中位数。
3. 任何一组出现持续 Draft timeout、Accept length 长期等于 1 或 Target 进程退出时，该组不能作为有效性能结果。
4. 每组至少保留 Target 日志、Draft 日志、benchmark JSONL 和 SpecStream profile CSV。
5. 创新点二、三的独立实验禁止使用 `--specstream-enabled`、History、H2D、Cohort 等创新点一参数；控制组使用 `--specstream-profile-only`，CPU/H2D 指标必须为 0。
6. 联合实验必须使用 `--specstream-enabled`；长输入下 `cpu_history_bytes`、`h2d_bytes`、`h2d_ops` 应大于 0。
7. 先完成 CPU/控制逻辑测试，再做 GPU 性能实验。
