# 创新点二与创新点三完整测试总览（含基线，易懂版）

版本日期：2026-08-22

说明：本文件保留为总览。实际执行请优先使用以 `创新点二_step`、`创新点三_step`、`创新点一与创新点二_step`、`创新点一与创新点三_step` 开头的“终端直接执行”文档。前两组不启用创新点一，后两组启用创新点一。

## 1. 测试目标

这份文档回答两个问题：

1. 第二点：把 Draft 和 Target 放在同一张卡上，是否能在少用一张 GPU 的同时保持较好的速度和尾延迟？
2. 第三点：Target 使用多卡 TP、Draft 与其中一个 Target rank 共卡时，是否能避免共卡 rank 拖慢整个 Target？

最重要的 baseline 是用户提出的“Draft 和 Target 分别使用不同 GPU 并行推测解码”。该 baseline 在两组实验中都必须运行。

## 2. 机器和软件要求

### 第二点

- 正式同卡实验：至少 1 张支持 CUDA MPS 的 NVIDIA GPU。
- 分卡 baseline：至少 2 张相同型号 GPU，Target 一张、Draft 一张。

### 第三点

- 推荐先做 TP=2。
- H1 共卡优化组：至少 2 张相同型号 GPU。
- H0 分卡 baseline：Target TP=2 使用 2 张卡，Draft 额外使用 1 张卡，所以至少需要 3 张卡。

### 软件

- Linux、NVIDIA Driver、CUDA、CUDA MPS。
- 已能正常启动 SGLang Target、SPECTRE Draft 和 benchmark。
- 每组实验使用完全相同的模型、数据集、随机种子、输入长度、输出长度、并发数和请求数。

先记录环境：

```bash
nvidia-smi -L
nvidia-smi
python --version
git rev-parse HEAD
```

## 3. 统一变量

以下命令中的尖括号内容需要替换为您机器上的真实值。

```bash
export TARGET_MODEL=<Target模型路径或名称>
export DRAFT_MODEL=<Draft模型路径或名称>
export TARGET_PORT=30000
export DRAFT_PORT=30001
export RESULT_ROOT=$PWD/results/specstream_$(date +%Y%m%d_%H%M%S)
mkdir -p "$RESULT_ROOT"
```

请准备三条已经能单独工作的完整命令：

```bash
export SPECSTREAM_TARGET_CMD='<完整Target启动命令>'
export SPECSTREAM_DRAFT_CMD='<完整Draft启动命令>'
export SPECSTREAM_BENCH_CMD='<完整benchmark命令>'
```

Target 命令至少要包含您原来启动 SPECTRE/SpecStream 所需的 Draft 地址和以下公共参数：

```bash
--specstream-profile-only \
--specstream-dynamic-q \
--specstream-q-candidates 1,2,4,6,8 \
--specstream-profile-path <本组输出CSV路径>
```

注意：不同 SGLang 版本的模型、Draft 地址和 benchmark 参数可能不同，所以脚本接收“完整命令”，不在脚本里硬编码模型路径。

## 4. 先做代码正确性测试

在仓库根目录运行：

```bash
export PYTHONPATH=python
pytest -q python/sglang/test/spectre_specstream
```

本次提交在当前工作区的结果是：49 passed，10 skipped。跳过项是必须有真实 CUDA GPU 或预先配置 TP 服务的测试。

如果 CPU 测试失败，先不要做性能实验。

## 5. 公平比较规则

所有组必须保持以下内容一致：

1. Target 模型、Draft 模型和精度一致。
2. 数据集、请求顺序和随机种子一致。
3. 输入长度、输出长度、并发数和总请求数一致。
4. q 候选集合一致。固定 q 实验则所有组使用相同 q。
5. 每组先预热，再正式运行至少 3 次；报告中间值，并保留每次结果。
6. 同一时刻不要运行其他 GPU 作业。
7. 每次切换 MPS 配额或 GPU 布局后，重新启动 Target 和 Draft。
8. 同时报告总吞吐和每张物理 GPU 的吞吐，避免“多用一张卡自然更快”造成误判。

## 6. 第二点：单卡内实验

### 6.1 实验组

| 编号 | GPU 放置 | MPS 配额 | 单卡策略 | 用途 |
|---|---|---:|---|---|
| S2-B0 | Target=GPU0，Draft=GPU1 | 无 | 关闭 | 核心 baseline：Draft、Target 分卡并行 |
| S2-B1 | Target=GPU0，Draft=GPU0 | 无 | 关闭 | 观察不隔离时是否互相抢资源 |
| S2-B2 | Target=GPU0，Draft=GPU0 | 90/10 | 关闭 | 静态 MPS baseline |
| S2-B3 | Target=GPU0，Draft=GPU0 | 80/20 | 关闭 | 静态 MPS baseline |
| S2-B4 | Target=GPU0，Draft=GPU0 | 70/30 | 关闭 | 静态 MPS baseline |
| S2-O1 | Target=GPU0，Draft=GPU0 | 最佳静态配额 | 打开 | 第二点完整优化 |

建议额外扫描 60/40。最佳静态配额不是预先指定，而是从 B2-B4 中按“速度、P99、Target slowdown”共同选择。

### 6.2 运行分卡 baseline S2-B0

先从 `nvidia-smi -L` 复制 GPU UUID，然后运行：

```bash
export SPECSTREAM_TARGET_VISIBLE_DEVICES=<GPU0_UUID>
export SPECSTREAM_DRAFT_VISIBLE_DEVICES=<GPU1_UUID>
export SPECSTREAM_RESULT_ROOT="$RESULT_ROOT/S2-B0-dedicated"
export SPECSTREAM_TARGET_CMD='<Target命令；不要加 --specstream-coexec-enabled>'
export SPECSTREAM_DRAFT_CMD='<Draft命令>'
export SPECSTREAM_BENCH_CMD='<benchmark命令>'
bash scripts/specstream/run_dedicated_draft_target_baseline.sh
```

这就是 Draft 和 Target 分别使用不同卡的并行推测解码 baseline。

### 6.3 启动 MPS

```bash
export SPECSTREAM_GPU_UUID=<GPU0_UUID>
source scripts/specstream/mps/start_mps.sh
```

确认 MPS 已运行后，再做同卡实验。结束全部实验时运行：

```bash
bash scripts/specstream/mps/stop_mps.sh
```

### 6.4 扫描静态配额 S2-B2 至 S2-B4

```bash
export SPECSTREAM_GPU_UUID=<GPU0_UUID>
export SPECSTREAM_QUOTA_PAIRS='90:10 80:20 70:30 60:40'
export SPECSTREAM_RESULT_ROOT="$RESULT_ROOT/step2_static_scan"
export SPECSTREAM_TARGET_CMD='<Target命令；关闭单卡动态策略>'
export SPECSTREAM_DRAFT_CMD='<Draft命令>'
export SPECSTREAM_BENCH_CMD='<benchmark命令>'
bash scripts/specstream/mps/run_static_percent_scan.sh
```

关闭单卡动态策略的含义是：Target 命令不加 `--specstream-coexec-enabled`。这样测到的是纯静态 MPS baseline。

### 6.5 运行第二点完整优化 S2-O1

先选出静态扫描中的最佳配额，例如 90/10，然后把 Target 命令增加：

```bash
--specstream-coexec-enabled \
--specstream-coexec-require-mps \
--specstream-coexec-draft-pressure-ratio 0.80 \
--specstream-coexec-timeout-rate-threshold 0.10 \
--specstream-coexec-pending-high-watermark 16 \
--specstream-coexec-compute-ratio-threshold 0.90
```

只运行所选配额：

```bash
export SPECSTREAM_QUOTA_PAIRS='90:10'
export SPECSTREAM_RESULT_ROOT="$RESULT_ROOT/S2-O1-single-gpu-policy"
bash scripts/specstream/mps/run_static_percent_scan.sh
```

### 6.6 第二点必须记录的结果

- 吞吐：每秒生成 token 数或每秒完成请求数。
- P50/P95/P99 延迟。
- Target slowdown：与 S2-B0 的 Target 速度相比慢了多少。
- goodput/GPU：满足延迟要求的有效吞吐除以物理 GPU 数。
- Draft 超时率、缺失结果数、回退次数。
- q 分布以及 COEXEC/THROTTLE/SERIALIZE/FALLBACK 次数。

建议通过以下脚本汇总 SpecStream CSV：

```bash
python scripts/specstream/summarize_specstream_profile.py \
  "$RESULT_ROOT"/**/specstream_profile*.csv \
  > "$RESULT_ROOT/specstream_summary.tsv"
```

### 6.7 第二点建议通过条件

第二点不是要求单卡绝对速度超过两卡 baseline，而是验证“少用一张 GPU 后，单位 GPU 效率更高，且延迟仍可接受”。建议至少满足：

1. 结果文本与 baseline 一致，不能出现正确性差异。
2. Draft 超时或缺失时能自动回退，不崩溃、不死锁。
3. 相比最佳静态 MPS，S2-O1 的 P99 不变差，或吞吐有稳定提升。
4. 相比 S2-B0，报告总吞吐差距，同时单独报告 goodput/GPU；不能只挑有利指标。

## 7. 第三点：多卡 TP 实验

### 7.1 实验组

| 编号 | Target | Draft | TP 保护 | 用途 |
|---|---|---|---|---|
| S3-B0 | GPU0+GPU1，TP=2 | 独占 GPU2 | 关闭 | H0 核心 baseline：Draft 与 Target 分卡 |
| S3-B1 | GPU0+GPU1，TP=2 | 与 GPU0 共卡 | 关闭 | H1 无保护对照 |
| S3-O1 | GPU0+GPU1，TP=2 | 与 GPU0 共卡 | 打开 | 第三点完整优化 |

### 7.2 运行 H0 分卡 baseline S3-B0

```bash
export SPECSTREAM_TARGET_VISIBLE_DEVICES=<GPU0_UUID>,<GPU1_UUID>
export SPECSTREAM_DRAFT_VISIBLE_DEVICES=<GPU2_UUID>
export SPECSTREAM_RESULT_ROOT="$RESULT_ROOT/S3-B0-H0-dedicated"
export SPECSTREAM_TARGET_CMD='<Target TP=2命令；关闭 TP 保护>'
export SPECSTREAM_DRAFT_CMD='<Draft命令>'
export SPECSTREAM_BENCH_CMD='<benchmark命令>'
bash scripts/specstream/run_dedicated_draft_target_baseline.sh
```

这是第三点最重要的对照：Target TP=2 使用两张卡，Draft 使用额外一张卡，总共 3 张物理 GPU。

### 7.3 运行 H1 无保护对照 S3-B1

Target 使用 GPU0、GPU1，Draft 也放 GPU0。先启动 MPS，Target 命令不要加 `--specstream-tp-straggler-control`，也不要加 `--specstream-coexec-enabled`。然后使用 H1 脚本运行。

```bash
export SPECSTREAM_TARGET_VISIBLE_DEVICES=<GPU0_UUID>,<GPU1_UUID>
export SPECSTREAM_DRAFT_GPU_UUID=<GPU0_UUID>
export SPECSTREAM_TARGET_SHARE=90
export SPECSTREAM_DRAFT_SHARE=10
export SPECSTREAM_RESULT_ROOT="$RESULT_ROOT/S3-B1-H1-no-control"
export SPECSTREAM_TARGET_CMD='<Target TP=2命令；关闭新增控制>'
export SPECSTREAM_DRAFT_CMD='<Draft命令>'
export SPECSTREAM_BENCH_CMD='<benchmark命令>'
bash scripts/specstream/mps/run_h1_colocated_tp.sh
```

### 7.4 运行第三点完整优化 S3-O1

在 S3-B1 相同布局和配额下，Target 命令增加：

```bash
--specstream-coexec-enabled \
--specstream-tp-straggler-control \
--specstream-colocated-tp-rank 0 \
--specstream-tp-straggler-budget-ms 1.0 \
--specstream-target-slowdown-budget 0.10 \
--specstream-tp-monitor-interval 8
```

然后运行：

```bash
export SPECSTREAM_RESULT_ROOT="$RESULT_ROOT/S3-O1-H1-tp-control"
bash scripts/specstream/mps/run_h1_colocated_tp.sh
```

### 7.5 第三点必须记录的结果

- 总吞吐、P50/P95/P99。
- goodput/GPU。S3-B0 除以 3 张物理卡；S3-B1/O1 除以 2 张物理卡。
- 每个 Target rank 的前向时间。
- 共卡 rank 与其他 rank 的时间差 `tp_rank_skew_ms`。
- `tp_target_slowdown`、SERIALIZE 次数、FALLBACK 次数。
- Draft 超时率、缺失结果数。
- `cpu_history_bytes`、`h2d_bytes`、`h2d_ops`，三者必须为 0，用来证明没有混入第一点。

### 7.6 第三点建议通过条件

1. 所有 TP rank 使用相同 q 和模式，结果正确，无死锁。
2. S3-O1 相比 S3-B1，rank 时间差和 P99 明显下降，且总吞吐不降低或降幅在预先接受范围内。
3. 与 S3-B0 同时报告总吞吐和 goodput/GPU。S3-O1 可以因为少用一张卡而总吞吐略低，但单位 GPU 效率应有竞争力。
4. 人为增大 Draft 压力时，先出现限 q 或 SERIALIZE；压力严重时能回到 q=1，而不是持续拖慢整个 TP 组。

## 8. 故障测试

每个完整优化组至少做一次：

1. 暂停 Draft 进程数秒，确认 Target 能超时回退。
2. 让 Draft 返回 REJECT，确认记录拒绝并限 q。
3. 恢复 Draft 后，确认系统经过短暂保守期能够继续推测解码。
4. 结束一条请求，确认没有残留请求状态或卡住的 GPU 工作。

故障测试不要与正式性能数据混在同一轮；单独保存日志。

## 10. 最容易犯的错误

1. baseline 和优化组用了不同模型、不同并发或不同请求数。
2. 只报告总吞吐，不报告用了几张物理 GPU。
3. S2 静态 MPS baseline 误开了单卡动态策略。
4. S3-B1 无保护对照误开了 TP 保护。
5. 修改 MPS 百分比后没有重启进程。
6. 用 GPU 编号代替 UUID，导致 MPS 实际绑定到错误设备。
7. Draft 尚未就绪就开始 benchmark。脚本支持 `SPECSTREAM_DRAFT_READY_CMD`；如果没有健康检查接口，至少保留默认预热时间。
8. 在第二点或第三点命令中误加 `--specstream-enabled`、cohort 或 History/H2D 参数，导致第一点混入结果。
